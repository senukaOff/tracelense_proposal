A recording is easy to share.
Trust takes more work.

TraceLense is proposed as an investigation assistant for disputed audio—helping people locate, understand and document areas that need expert attention.

02 / THE MULTI-ENGINE CONCEPT

Many signals.
One accountable case.

Like cylinders in an engine, each module contributes a different signal. More modules do not automatically mean more certainty. Select a module to explore its role.

Evidence orchestrator
Always on

Protect the source.

Hash the original file with SHA-256, retain it unchanged and inspect its metadata with FFprobe. Log every derivative and action. A matching hash shows integrity since intake; it does not prove that a recording was genuine before upload.

Quick screening

Integrity + metadata + one local detector. Lower cost; narrow coverage.

Standard investigation

Local signals + models + optional speech tools. Recommended pilot default.

Extended review

Selected vendor checks and expert review. Additional cost and data permissions.

Model scores stay separate until fusion is validated. Correlated models are not independent witnesses. No simple average, no unsupported “probability of being fake,” and no court-ready label at MVP.

Licensing, security and model selection

Check exact code, model-weight and dataset terms before commercial use. Whisper states MIT licensing; Community-1 lists CC-BY-4.0 and access conditions. Retest against new generators, compression and re-recordings.

What must pass before wider release?

Measure false positives, missed detections, transcript and speaker errors, uncertain outcomes, latency and cost by language and recording condition. Test genuine, synthetic, partially synthetic and conventionally edited recordings with documented rights. Separate evaluation data from tuning data; include unseen speakers and generators. Publish sample sizes, uncertainty and unsupported conditions. Security gates include tenant-isolation tests, access reviews, backup restoration and a penetration test. Define customer service targets and model acceptance criteria before the pilot, then assess measured results against them.

What changes the real bill?

The small EC2 server hosts web/API services; heavy models run on separate workers. T3 CPU-credit usage and memory pressure must be measured. The lean profile has no load balancer or NAT gateway: only the app entry point is internet-facing, the database stays private, and GPU workers need a controlled egress route. An IPv4/egress allowance is included for workers; private NAT or interface endpoints require a revised estimate. The managed profile includes two CPU tasks, a load balancer allowance, Multi-AZ database allowance and two-AZ NAT/network allowance; it is still an illustrative design, not a production sizing approval. Static storage allowances assume a small pilot: 100 GB evidence for lean, 300 GB managed, plus a 100 GB model disk. Include duplicated evidence, logs, snapshots, image pulls and audit retention when sizing. Track CPU/GPU runtime, billable API units, retries and storage, then reconcile with invoices. Provider versions, minimum duration and overlapping windows can affect billing.

Fargate is the proposed CPU service path; this design uses GPU-backed EC2 for model acceleration. ECS coordinates containers; EC2 supplies machines. AWS Batch can queue GPU jobs and allow compute capacity to return to zero.
01 · Reduce idle time

Pay for active workers.

Batch jobs, preload model images and stop idle GPU capacity. Allow for cold starts, image pulls and model loading in billed time.

02 · Spend on the right checks

Route with a purpose.

Start with local checks. Use vendor calls only when permitted and useful. Validate segment length and coverage before trimming requests.

03 · Use Spot carefully

Trade speed for savings.

Use interruptible capacity for retryable jobs. Persist progress, cap retries and keep an On-Demand fallback for urgent cases.

04 · Keep compute efficient

Test smaller footprints.

Benchmark quantisation and smaller speech models. Use ARM for compatible CPU services. Keep changes only if quality holds.

05 · Control stored data

Retain with intention.

Set evidence retention and archive rules. Cache results only within the same authorised case/tenant and exact model configuration.

06 · Commit after measuring

Optimise the steady load.

Consider Savings Plans for stable usage. Review NAT, endpoints, logs and idle disks—small services can become a large fixed bill.

09 / MARKET POSITION & GROWTH

Win a narrow workflow.
Earn the right to expand.

Begin with a small number of investigation partners. Sell a controlled review process, measured usefulness and transparent limitations.

01 · Discover

Interview 10–15 legal, investigation and verification teams. Recruit 3 design partners. Validate case volume, confidentiality needs and willingness to pay.

02 · Demonstrate

Use permissioned case studies, side-by-side workflows and measured review-time savings. Partner with examiners rather than promising to replace them.

03 · Monetise

Test per-case screening and team subscriptions. Price expert services separately. Pass through external API usage; quote private deployments individually.

Competitive reality → proposed differentiation

AuriginInspect already competes.It markets layered forensic analysis and reports. Workflow alone is not a unique category claim. [3]

Resemble can be a partner or rival.Its detector API is an optional component. TraceLense must add customer value beyond reselling its output. [1]

Our proposition must be proven.Configurable local processing, interchangeable engines, edit + synthesis review, target-language evaluation and transparent case costs.

Evidence of commercial value

Measure before marketing.

Target: 3 active pilot partners, ≥30% reduction in median review preparation time, and at least 2 partners willing to pay. Compare like-for-like cases and preserve review quality. These are proposed targets, not achieved outcomes.

A defensible message

“Audio evidence, made traceable.”

Position the MVP as audio authenticity screening and investigation support. Publish limitations and tested conditions. Avoid “guaranteed AI detection,” “court-certified,” or unsupported language-coverage claims.
